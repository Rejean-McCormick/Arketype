# Arketype — contributor and agent guidance

Arketype is a **non-normative design library**. It is not a new Kristal Framework, an authority over existing states, or an operational system.

- Preserve legacy Local Authoring Kit 3.2.4 **inside all 19 historical templates** and stable technical identifiers. New v11-ready workspaces opt in to separately bundled Authoring Kit 4.0.0-draft.3.
- Treat `archetypes/`, `assemblages/`, `design/`, and `arketype.template.json` as descriptive, noncanonical metadata.
- Instantiation must create a new slug and `state_ref`; the owner must ensure uniqueness in the real deployment.
- Never assume permission to publish, activate, access private data, or execute operational procedures.
- Do not copy an external committed knowledge state where an exact pinned reference is required.
- Composition recipes are design plans. Define semantic ownership and interfaces before accepting logical artifacts.
- Run the library tests and Authoring Kit `check` commands; `build-v9` is not publication or factual qualification.
- Update the relevant source JSON, descriptive docs, generated views and tests together when a design changes.

## Usage-aware design (1.4.0)

- Keep structure, usage, domain, integrations and authority/data boundaries independent. Do not create a new archetype solely for a new application domain.
- Update `inventaires/profils-usage.json`, descriptive assembly JSON, situated diagrams, contracts, offline HTML, printable PDF, Wiki and regression tests together.
- Recognition inspects bounded metadata and paths, not canonical records or confidential casefiles; do not claim it verifies semantic completeness.
- `arketype.scope-guidance/1.0` is NOT the Skope injection contract; no automatic `state_scope` mutation or external application side effects are permitted.
- Never grant patient, student, employee, cultural or legal data access by inheriting an archetype or profile.

## Framework v11 and diK boundaries (1.6.0)

- Arketype is a design library; semantic KQ/KP labels and Wikidata Q/P MUST NOT be invented in designs.
- Only `(namespace_id,KQ/KP)` identifies semantics in admitted Framework v11 graphs. Design labels and diagram node names remain noncanonical and multilingual.
- The new v11 option creates **empty** Kit v4 workspaces with a readiness checklist; `enable-v11` is a separate reviewed Kit action after KQ/KP/KA/KS registry and graph/crosswalk/catalog registration.
- diK completeness reports are **read only**. A non-normalized legacy Kristal cannot claim full KQ/KP coverage; crosswalk or lexical similarity is never proof of exact identity.
- Legacy templates, their state references, and v9 commitments are preserved. Do not rewrite frozen source states to migrate them.
- The user supplied the original approved SVG logo; bundled `assets/logo-k.svg` is the exact user-supplied approved logo; `assets/logo-k-ui.png` is rendered from that SVG. Preserve the original asset bytes.
